# Benchmarks (v0.1.0-alpha.1)

Measured on 2026-11-07. These are single-machine sanity numbers from one
run each, not a performance claim or an SLA. They exist to show the order of
magnitude and to catch regressions such as a full graph scan per row.

## Environment

| | |
|---|---|
| Host | Apple M4, 10 cores, 16 GB RAM, macOS 15 (Darwin 24.5) |
| Containers | Podman 6.1 machine (applehv), 6 vCPUs, 8 GiB; other unrelated containers were running |
| Stack | `docker-compose.yml` from this release (isolated project `mindgraph-smoke`): HugeGraph 1.7.0 with a 1 GiB heap, PostgreSQL 17, Core built `--release` in Docker |
| Data | synthetic: `customers.csv` (`customer_id,name,city`) and `accounts.csv` (`account_id,customer_id,balance`), one account per customer; the fraud demo for queries |
| Client | the REST API on `127.0.0.1` (Python standard library), or the in-process test harness where noted |

## Ingestion

Through the REST API of the Compose stack (upload, analysis job, ingestion
job polled every 50 ms; times are wall clock as seen by the client):

| Rows | File | Upload | Analysis | Ingestion | Throughput | Result |
|---|---|---|---|---|---|---|
| 1,000 | customers | 7 ms | 64 ms | 0.17 s | ≈ 5,800 rows/s | 1,000 entities created |
| 1,000 | accounts | 3 ms | 59 ms | 0.34 s | ≈ 3,000 rows/s | 1,000 created, 1,000 customers matched, 1,000 relationships |
| 10,000 | customers | 4 ms | 60 ms | 0.45 s | ≈ 22,000 rows/s | 10,000 entities created |
| 10,000 | accounts | 7 ms | 56 ms | 3.71 s | ≈ 2,700 rows/s | 10,000 created, 10,000 matched, 10,000 relationships |

The in-process harness (`cargo test --release -p mindgraph-api --test
ingestion_perf -- --ignored --nocapture`, 10,000 + 10,000 rows, analysis and
ingestion only, no HTTP):

| Store | customers (create) | accounts (create + match + relate) |
|---|---|---|
| in-memory GraphStore | 34 ms (≈ 295,000 rows/s) | 1.27 s (≈ 7,800 rows/s) |
| HugeGraph 1.7 (1 GiB heap, separate container) | 0.73 s (≈ 13,700 rows/s) | 4.73 s (≈ 2,100 rows/s) |

Rows that create and link entities are slower than rows that only create:
each batch looks up the existing identities it matches and checks for
existing relationships before writing.

## Graph queries

Fraud demo graph (35 entities, 27 relationships) through the REST API,
30 runs after one warm-up:

| Query | p50 | p95 |
|---|---|---|
| exact search (`Customer customer_id = C001`) | 1.7 ms | 2.0 ms |
| neighbours of Alice Tan (both directions, limit 100) | 2.1 ms | 2.9 ms |
| shortest path C001 → C002 (2 hops, max depth 3) | 4.1 ms | 6.6 ms |
| shortest path C001 → M004 (3 hops, max depth 6) | 4.6 ms | 8.2 ms |

Path search on HugeGraph reads the relationships of each entity it expands
(one request each) and stops after 2,000 entities, so its time grows with the
size of the explored neighbourhood, not with the graph.

## Entity resolution

| Scan | Entities | Pairs compared | Candidates | Time |
|---|---|---|---|---|
| fraud demo, via the API (3 rules) | 13 | n/a | 7 | 2.8 ms p50, 3.4 ms p95 (10 runs) |
| pure matching, 300 customers + 100 injected duplicates | 400 | 4,667 | 144 (all 100 injected found) | 47 ms |
| pure matching, largest allowed scan | 999 | 20,000 (comparison budget reached) | 316 (193 of 199 injected found) | 55 ms |

Pure matching numbers come from `cargo test --release -p
mindgraph-entity-resolution --test scan_perf -- --nocapture` and exclude
reading entities from the GraphStore.

## Web app

Navigation timing of warm page loads from the Compose stack on `127.0.0.1`
(gstack headless browser, `perf`): Home 71 ms, Demos 17 ms, Graph Explorer
shell 24 ms to the `load` event. These cover the page itself, not the API
calls the page makes afterwards or WebGL rendering (the headless browser
has no GPU).

## Resource use

With the three demos loaded and idle: HugeGraph ≈ 725 MB, web ≈ 80 MB, AI
service ≈ 44 MB, PostgreSQL ≈ 39 MB, Core ≈ 4 MB of memory. Images: HugeGraph
723 MB, web 323 MB, PostgreSQL 294 MB, AI 231 MB, Core 143 MB.

## Not measured

- Graphs beyond 10,000 + 10,000 rows, concurrent users or concurrent jobs.
- Ask MindGraph and the AI Graph Builder: their time is dominated by the
  model provider, which varies by provider and is not called in these runs.
- Linux hosts and x86_64 CPUs.

## Reproduce

```bash
cargo test --release -p mindgraph-api --test ingestion_perf -- --ignored --nocapture   # needs make hugegraph-test-up for the HugeGraph case
cargo test --release -p mindgraph-entity-resolution --test scan_perf -- --nocapture
```
